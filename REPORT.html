1. Abstract

The Faculty Feedback Web Application is a web-based system developed to collect structured feedback from students about faculty members and subjects. Traditional feedback methods such as paper forms or informal messages can make it difficult to organize responses, calculate ratings, and protect student identity.

The application provides a centralized digital form where students select their class, division, roll number, faculty member, subject, and ratings for teaching quality, communication, and subject knowledge. Students can also provide comments and contact details when required.

The application is developed using HTML, CSS, JavaScript, PHP, and MongoDB. HTML creates the feedback form, CSS controls the presentation, JavaScript performs client-side validation and calculates the overall rating, and PHP performs server-side validation and database operations.

The system supports anonymous feedback. When anonymity is selected, the student's name, email ID, phone number, and roll number are removed before storage. Class and division are retained for academic reporting without exposing the student's identity on the dashboard.

A separate dashboard displays submitted feedback, total responses, average rating, student classification, and anonymous or identified status. The project demonstrates the practical integration of frontend development, client-side interaction, server-side programming, validation, privacy, and database management.

2. Introduction

Faculty feedback is an important part of academic improvement. Students can provide useful information about teaching quality, communication, subject knowledge, and their overall learning experience. When feedback is collected manually, records may be incomplete, difficult to compare, and difficult to protect.

The proposed Faculty Feedback Web Application provides an organized approach to collecting and reviewing student responses. Students submit feedback through an online form, while the PHP backend validates the request and stores the response in MongoDB.

The system follows a client-server architecture. The client side consists of HTML, CSS, and JavaScript. HTML defines the form, CSS provides the visual design, and JavaScript provides rating interaction, character counting, and immediate validation.

The server side is implemented using PHP. PHP receives the submitted form data, validates every important field again, calculates the trusted overall rating, removes identifying data for anonymous feedback, and inserts the document into MongoDB.

The application separates feedback creation from feedback management. A student uses the feedback form, while an authorized staff member can open the dashboard to review stored responses and summary statistics.

3. Problem Statement and Objectives

3.1 Problem Statement

Manual faculty feedback processes can create difficulties in collecting accurate and consistent responses. Students may omit important information, ratings may be entered outside the expected range, and feedback records may not be easy to summarize.

Student privacy is another important concern. A feedback system should allow students to share honest opinions without unnecessarily exposing their personal information. The system must also ensure that invalid requests cannot be inserted by bypassing the browser.

3.2 Objectives

  1. To develop a web-based faculty feedback system.
  2. To provide a simple and user-friendly student feedback form.
  3. To collect class, division, roll number, and student details.
  4. To support independent roll numbers across different divisions.
  5. To validate feedback in both JavaScript and PHP.
  6. To calculate a reliable overall rating from three rating categories.
  7. To store feedback records in a structured MongoDB collection.
  8. To provide an anonymous submission option.
  9. To display feedback summaries through a dashboard.
  10. To demonstrate practical use of HTML, CSS, JavaScript, PHP, and MongoDB.

5.6 Division-wise Student Identity

Student identity is treated as a combination of class, division, and roll number. This allows the same roll number to be used independently in different divisions. For example, TE IT Division A Roll No. 15 and TE IT Division B Roll No. 15 are separate student records.

Class + Division + Roll Number is the logical student identity used by the feedback form. The current form supports SE IT, TE IT, BE IT and Divisions A, B, C, and D.

7. Privacy and Anonymous Feedback

7.1 Anonymous Submission

The form provides a checkbox at the end of the form named "Submit this feedback anonymously". This lets a student decide whether the submitted feedback should be identified or anonymous after entering all details.

When selected, PHP changes the stored name to Anonymous and removes the email, phone number, and roll number before inserting the MongoDB document. The dashboard also masks these fields and marks the response as Anonymous.

7.2 Reporting Information

Class and division remain available for academic reporting. This allows staff to compare feedback across divisions without exposing the student's name or contact details. The privacy behavior is therefore practical for class-wise analysis while protecting individual identity.

7.3 Dashboard Presentation

The dashboard shows total feedback and average rating, followed by a table containing student classification, feedback type, faculty, subject, individual ratings, overall rating, and comments.

Privacy principle: anonymous mode is applied before database insertion, so identifying values are not merely hidden visually; they are not retained in the anonymous record.

8. PHP and MongoDB Backend

8.1 Database Connection

The db.php file creates a MongoDB driver manager using the MONGODB_URI environment variable. The default local URI is mongodb://127.0.0.1:27017 and the default database is faculty_feedback.

8.2 Server-side Processing

The submit.php file accepts POST requests only. It validates allowed classes, divisions, faculty members and subjects, checks numeric limits, verifies contact fields, calculates the overall rating, applies anonymous privacy, and inserts the final document.

8.3 Error Handling

Invalid requests receive an HTTP 422 response. Database connection failures receive an HTTP 500 response. Invalid request methods receive an HTTP 405 response.

10. Implementation and Results

The application was implemented and tested locally using XAMPP PHP and MongoDB. The frontend loads from the PHP development server or Apache, while the backend communicates with the MongoDB database.

10.1 Feedback Submission

After valid information is submitted, the PHP backend creates a feedback document. The overall rating is calculated from the three category ratings and the submission is displayed through the dashboard.

10.2 Validation Testing

  • Empty required fields are rejected by the browser and backend.
  • Invalid email addresses are rejected.
  • Invalid phone numbers are rejected.
  • Roll numbers outside 1-100 are rejected.
  • Ratings outside 1-5 are rejected.
  • Comments longer than 250 characters are rejected.
  • Manipulated overall ratings are recalculated and rejected.

10.3 Privacy Testing

Identified submissions display student details. Anonymous submissions display Anonymous and do not retain identifying contact fields or roll number in the stored document.

The connection test endpoint confirmed that MongoDB is connected successfully through XAMPP PHP.
